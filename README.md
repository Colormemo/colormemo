## Первый запуск

Нужны: [Node.js 22](https://nodejs.org/) и [Docker Desktop](https://www.docker.com/products/docker-desktop/).

### На маке (Маша)

```bash
git clone <адрес репозитория>
cd colormemo

npm install                       # зависимости всех пакетов сразу
docker compose up -d              # база на порту 5433 + Adminer на 8080

cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env.local

npm run build:shared              # общий пакет надо собрать первым

cd backend && npx prisma migrate dev --name init && cd ..
```

Дальше в двух терминалах:

```bash
npm run dev:back     # http://localhost:3000, документация на /api/docs
npm run dev:front    # http://localhost:5173
```

### На Windows (Настя)

Всё то же самое, но два условия:

1. **Работать в WSL, а не в PowerShell.** Установка: в PowerShell от администратора `wsl --install`, перезагрузка. Дальше все команды — в терминале Ubuntu.
2. **Репозиторий должен лежать внутри WSL**, например в `~/projects/colormemo`, а не в `/mnt/c/Users/...`. На диске Windows Docker и сборка работают в разы медленнее.

Один раз настроить Git, чтобы не воевать с переносами строк:

```bash
git config --global core.autocrlf false
```

В Docker Desktop включить интеграцию с WSL: Settings → Resources → WSL integration.

Если контейнер не поднимается с ошибкой про доступ к сокету — порт занят системой Windows. Поменяйте `5433` в `compose.yaml` и `DATABASE_URL` на другой, например `5434`.

## Работа без бэка

Пока авторизации и статистики нет, фронт умеет работать на заглушках: в `frontend/.env.local` стоит `VITE_USE_MOCK=true`. Заглушки лежат в `frontend/src/api/mock.ts` и повторяют контракт настоящего API, включая подсчёт очков.

Что это даёт: игры можно писать и проверять целиком, а когда API будет готов — поменять флаг на `false`, и ни одна строка игрового кода не изменится.

## Как мы договорились работать

**Ветки.** В `main` не пушим напрямую. На каждую задачу своя ветка: `feature/game-color-choice`, `feature/auth`, `fix/timer-reset`. Дальше пул-реквест, вторая смотрит код, потом слияние.

**Разделение зон.** Настя — бэк, база, авторизация, статистика. Маша — фронт, игровая логика. Пересекаемся в `packages/shared`: любую правку контракта обсуждаем до кода, потому что она ломает работу обеим.

**Регистр в именах файлов.** Компоненты — `PascalCase.tsx`, остальное — `kebab-case.ts`. Импорт пишем ровно так, как называется файл. На маке и Windows регистр не важен, а на Linux (в контейнере и на GitHub) важен — иначе сборка развалится там, где мы этого не увидим.

**Параметры игр.** Только в `packages/shared/src/difficulty.ts`. Никаких «магических» чисел в компонентах: после тестирования на людях баланс придётся крутить.

## Публикация

### Фронт — GitHub Pages, бесплатно

Настроить один раз: **Settings → Pages → Source: GitHub Actions**. После этого каждый пуш в `main` публикует сайт сам.

Важно про имя репозитория:

- репозиторий с именем `ИМЯ-ОРГАНИЗАЦИИ.github.io` отдаётся из корня домена — меньше возни;
- любое другое имя даёт адрес `ИМЯ-ОРГАНИЗАЦИИ.github.io/ИМЯ-РЕПОЗИТОРИЯ/`, и сборке нужен базовый путь. Workflow вычисляет его сам из имени репозитория, вручную ничего писать не надо.

**Репозиторий должен быть публичным.** На бесплатном тарифе Pages не работает с приватными репозиториями. Отсюда правило: никаких паролей и секретов в коде. Всё чувствительное — только в `.env` (он в `.gitignore`) и в Secrets репозитория.

### Бэк — Pages не подойдёт

GitHub Pages отдаёт только статические файлы: Node и PostgreSQL там не запустятся. Варианты, все бесплатные:

| Где                     | Плюсы                                          | Минусы                                                              |
| ----------------------- | ---------------------------------------------- | ------------------------------------------------------------------- |
| **Render** (Free)       | Бесплатно, деплой из GitHub, есть Docker       | Засыпает после 15 минут без запросов, первый запрос ждёт ~50 секунд |
| **Fly.io**              | Не засыпает, быстрый                           | Просит привязать карту даже на бесплатном тарифе                    |
| **Neon** / **Supabase** | Бесплатный PostgreSQL, этого хватает с запасом | —                                                                   |

Рабочая связка: **фронт на Pages + бэк на Render + база в Neon.** Ноль рублей.

Что прописать после деплоя бэка:

1. В переменных репозитория (Settings → Secrets and variables → Actions → Variables) создать `VITE_API_URL` с адресом бэка. Пока её нет, сайт публикуется на заглушках и всё равно работает — удобно показывать прогресс.
2. В переменных окружения бэка на Render: `DATABASE_URL` из Neon, `JWT_SECRET` (длинная случайная строка), `CORS_ORIGINS` с адресом сайта на Pages.

**Про cookie между доменами.** Сайт и API будут на разных доменах, поэтому cookie с токеном должна ставиться с `sameSite: 'none'` и `secure: true`, иначе браузер её просто не сохранит. Для локальной разработки — `sameSite: 'lax'`. Это частая причина «авторизация работает локально и не работает на проде».

**Перед защитой:** бесплатный Render засыпает. Откройте сайт за пару минут до показа, чтобы бэк успел проснуться. Запасной вариант — поднять всё локально через Docker на ноутбуке.

Кстати, стоит оформить [GitHub Student Developer Pack](https://education.github.com/pack) по студенческой почте: даёт бесплатный GitHub Pro (а с ним Pages для приватных репозиториев) и кучу бесплатных сервисов.
