# Фронтенд

Vite + React + TypeScript. Запуск описан в README в корне репозитория.

## Из чего состоит

```
src/
├── routes.ts          адреса страниц в одном месте
├── App.tsx            маршрутизация
├── api/               единственный модуль, который знает про сеть
├── auth/              кто вошёл, форма логина и пароля, защита маршрутов
├── layout/            шапка и навигация
├── pages/             страницы разделов
├── components/        состояния загрузки, пусто, ошибка
├── lib/               загрузка данных с повтором
└── features/games/
    ├── useGameSession.ts  ОБЩИЙ ИГРОВОЙ ЦИКЛ — он один на все игры
    ├── GameScreen.tsx     каркас экрана: раунды, отсчёт, разбор, итоги
    ├── ColorChoiceGame.tsx
    ├── ColorRecallGame.tsx
    └── catalog.ts         список игр для экрана выбора
```

## Как устроена игра

Цикл одинаков у всех игр: запросили задание — показали на время — спрятали —
приняли ответ — показали разбор — следующий раунд, и так пять раз, затем итоги
серии. Этот порядок живёт в `useGameSession`, а конкретная игра приносит
только три куска разметки: чем показываем задание, чем на него отвечают
и как выглядит сравнение «было / выбрали».

Поэтому третья игра из плана-максимум не потребует трогать цикл — достаточно
будет написать свои три куска по образцу `ColorChoiceGame.tsx`.

## Правила, о которых легко забыть

- **Время ответа** считать через `performance.now()`, а не `Date.now()`:
  не сбивается, если у игрока подвинулись системные часы.
- **Таймеры** складывать в `useRef` и гасить при уходе со страницы, иначе
  отсчёт продолжит работать и попробует обновить снятый с экрана компонент.
- **Параметры уровней** — только в `packages/shared/src/difficulty.ts`.
- **После правок общего пакета** запускать `npm run build:shared`,
  иначе фронт подхватит старую версию.
- **Интерфейс не красить.** Любой насыщенный цвет рядом с образцом смещает
  восприятие оттенка, поэтому фон серый, кнопки чёрные, а вся краска
  приходит из самих заданий. Это условие измерения, а не стиль.

## Запросы к серверу

Адреса относительные: фронт и API на одном домене. В разработке `/api` уводит
на `localhost:3000` прокси Vite (`vite.config.ts`), в готовом виде тот же
сервер отдаёт и сайт, и API. Настраивать адрес сервера не нужно нигде.

Сессия держится на httpOnly-cookie — токена в коде страницы нет и быть
не должно.
